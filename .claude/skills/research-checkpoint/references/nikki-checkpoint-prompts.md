# Nikki Anderson's Checkpoint Prompts

These prompts are from Nikki Anderson's article "Use AI Across Your User Research Process" (userresearchstrategist.com). They are tools to deploy situationally during mid-study checkpoints — not a sequence to walk through mechanically.

**Important:** These prompts should be adapted to the interactive, question-driven style defined in CLAUDE.md — do not output all sections at once. Walk through them conversationally, reflecting back and checking understanding at each step. The user provides only their own summaries and interpretations, never raw data.

---

## Prompt 1: Mid-Study Insight QA

### When to use it
When the user is partway through sessions and starting to see patterns, but risks jumping to conclusions, missing nuance, or over-interpreting early signals. Mid-study overconfidence is one of the easiest ways to steer a project off course.

### Logic to follow
1. **Identify possible misinterpretations.** Where might the user be overinterpreting, oversimplifying, or assigning intent to users without enough evidence?
2. **Spot missing evidence.** What user behaviors, patterns, or data points haven't been gathered yet that are needed to validate or challenge these early insights?
3. **Pressure-test alternative explanations.** Suggest 3–5 alternative explanations for the patterns being observed.
4. **Identify risks of premature conclusions.** What could go wrong if the team acts on these early patterns too quickly?
5. **Suggest adjustments.** Recommend changes for the next round of sessions to strengthen evidence quality.

### Follow-up angles
- Draft a short internal update summarizing what's still uncertain
- Suggest which participants to target next to fill gaps
- Identify where bias might be creeping in

## Prompt 2: Hypothesis Stress-Test

### When to use it
When the user has formed working hypotheses based on early evidence and needs to check whether the logic holds before presenting anything. Hypotheses formed mid-study can be insightful or completely off-base.

### Logic to follow
1. **Identify weak points.** Where does each hypothesis feel fragile or under-supported?
2. **Identify strengthening and weakening evidence.** What behaviors, observations, or evidence would be needed for validation?
3. **List alternative hypotheses.** Suggest 3–5 rival hypotheses that could also explain the observed patterns.
4. **Identify failure modes.** If the hypothesis is wrong, what would the real pattern likely be?
5. **Recommend next steps.** What should be prioritized in upcoming sessions to validate or challenge these hypotheses?

### Follow-up angles
- Rewrite each hypothesis to be more testable
- Identify where the user might be anchoring too early
- Suggest specific questions or probes to add to upcoming sessions

## Prompt 3: Friction Spotting

### When to use it
When the user is reviewing session notes and something feels off — a moment where users hesitated, struggled, or expected something different. Helps articulate observed friction with precision.

### Logic to follow
1. **Categorize the friction.** Classify each friction point as cognitive, emotional, navigational, trust-related, value-related, expectation mismatch, or effort-related.
2. **Identify root causes.** For each friction point, suggest what might be causing it based on patterns so far.
3. **Map user impact.** For each friction point, describe how it might alter user behavior, motivation, trust, or progress.
4. **Identify product impact.** Which outcomes, flows, or metrics might shift due to these friction points?
5. **Suggest follow-up investigation.** Provide questions, probes, or tasks to explore these friction points in the next sessions.

### Follow-up angles
- Summarize top friction points for a stakeholder slide
- Identify which frictions have the highest impact on conversion or retention

## Prompt 4: Mid-Flight Course Correction

### When to use it
When something has changed during the study — the prototype was modified mid-study, the team added new questions, user behavior is surprising, or external context shifted. When the plan needs adjusting without sacrificing insight quality.

### Logic to follow
1. **Identify how the change affects the study.** Which parts of the plan are now at risk? Where could insight quality drop?
2. **Recommend adjustments.** Propose concrete changes to the plan that preserve insight quality.
3. **Identify what to deprioritize.** Which parts of the original plan should be paused or removed?
4. **Recommend next-session focus.** What should be probed more deeply, added, or clarified in upcoming sessions?
5. **Draft a stakeholder update.** A concise update explaining the shift, the adjusted plan, and how quality is being protected.

### Follow-up angles
- Rewrite the update in a more direct, executive-ready tone
- Surface risks of not adjusting the plan
- Help communicate changes without sounding defensive
